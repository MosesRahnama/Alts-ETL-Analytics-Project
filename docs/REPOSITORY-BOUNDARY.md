# Files Git tracks

Git tracks the whole project: code, field lists, prompts, evidence CSVs, fund-model CSVs, review files, tests, folder guides, the dashboard, and the data. The large and binary files go through Git LFS, routed by `.gitattributes`: source PDFs, page-aligned text, the three DuckDB files, the market Parquet files, and the six large fixture tables.

| Stays out of Git | Reason |
|---|---|
| `data/documents/images/**/*.png` | 300 DPI page pictures are large files. Extraction requires them. Git tracks `MANIFEST.csv`. Each machine writes the PNG files with `data-gathering/src/render_image_corpus.py`. |
| `archive/artifacts/` | content-addressed backups of replaced outputs; the receipts stay tracked |
| `notes.md`, `diagnostics.md` | the operator's working brief and defect ledger |
| caches and `.part` files | regenerated by every run |

`docs/PROJECT-MANIFEST.csv` records each path, size, SHA-256, repository policy, folder guide, and role. `TRACK` marks a file Git carries; `LOCAL_ONLY` marks a file on the local mirror that Git leaves out. A clone with LFS fetched holds every file the checks read; a clone without LFS holds pointers in place of the PDFs, text, Parquet, and databases, and the checks that read those say so.
